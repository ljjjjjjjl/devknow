## 第六周 · 拒答机制失效排查

> 排查日期：2026-10-16
> 触发场景：演示页联调时问「如何实现异步任务」，模型答"检索到的内容中没有直接回答……"，随后补了一段通用知识
> 结论：不是模型不听话，是硬约束的**分支没写全**

### 现象

输出分两段：

| 段 | 内容 | 判定 |
|---|---|---|
| ① | "检索到的内容中没有直接回答……的具体方法或代码示例。" | 正确，检索确实没拿到答案 |
| ② | "以下是异步任务的常见实现方式（基于通用知识）：" + 一段通用做法 | 违规，违背"检索不到时明确说不知道" |

问题只在 ②。① 反而说明模型**知道**检索结果不相关 —— 它只是没把"那就该说不知道"接上。

## 排查链路

### 第 1 步 · 读提示词的运行时真值

三处都读，重点看**数据库里的那份**：

- `devknow-agent/src/main/java/com/devknow/agent/engine/AgentRunner.java` 的平台级追加约束
- `devknow-web/src/main/resources/db/migration/V5__seed_agent_config.sql`
- `agent_config` 表实际值（`SELECT system_prompt FROM agent_config WHERE name='devknow-default'`）

三处都用「检索不到」/「检索不到相关内容」表述 —— **二元分支**，没有第三种情况的规则。

- 排除：提示词丢失、没被加载
- 锁定：约束本身有覆盖漏洞

### 第 2 步 · 读工具实现，看 0 命中返回什么

`devknow-agent/src/main/java/com/devknow/agent/tool/SearchKnowledgeTool.java` 的 0 命中分支返回固定文本「未检索到相关内容」。

同时发现**日志盲区**：`search_knowledge` 的成功日志只写在非空分支，0 命中直接 `return`，**一行日志都没有**。事后翻日志分不清「没命中」和「压根没调用工具」，而这两种情况的排查方向完全相反。

### 第 3 步 · 打检索接口，看实际返回

- 第一次 `curl.exe -d '{...中文...}'` 返回 HTTP 500（内联中文参数被编码搞坏，见坑表），换 `--data-binary @文件` 才 200
- 真实返回 **5 条**，不是 0 条：

| # | rerankScore | 标题 |
|---|---|---|
| 1 | 0.312 | Task Execution and Scheduling |
| 2 | 0.074 | Running Your Application |
| 3 | 0.062 | fix: use first available executor when applicationTaskExecutor… |
| 4 | 0.051 | Springdoc + actuator + long generation + spring.thre… |
| 5 | 0.051 | Running your Application with Maven |

- 排除：「工具返回 0 条」与「工具执行失败」两个假设都不成立 —— 模型收到的是「检索到 5 条结果」

### 第 4 步 · 查语料覆盖面（此步结论后被修正）

`document_chunk` 里含 `@Async` 或 `EnableAsync` 的有 12 chunk / 6 篇，其中 `document 2230` = `Task Execution and Scheduling`（Spring Boot 官方异步章节），**而且它就是检索第 1 名**。

当时据此判定"语料覆盖假设证伪"。

**错在把"关键词命中"当成了"语义覆盖"** —— 只查了"库里有没有这个词"，没查"库里那段是不是答案"。

### 第 5 步 · 量化相关度，发现没有下限

单看 0.312 无法判断好坏，必须有对照分布。抽 9 条 query 打 top-1 精排分：

| 类型 | query | top-1 |
|---|---|---|
| 库内确有答案 | Spring Boot 里怎么配置 JTA 分布式事务？ | 0.995 |
| 库内确有答案 | Spring Boot 里怎么用 @Async 做异步任务？ | 0.899 |
| 库内确有答案 | @JsonTest 之外还有哪些测试切片注解？ | 0.801 |
| 库内确有答案 | Jakarta Json Bind 3.0.3 升级要注意什么？ | 0.740 |
| **本次出问题** | **如何实现异步任务** | **0.318** |
| 明确库外 | 如何用 Rust 写一个操作系统内核 | 0.010 |
| 明确库外 | 红烧肉怎么做才好吃 | 0.004 |
| 明确库外 | 推荐几部科幻电影 | 0.002 |

两个发现：

- 库内与库外差**两个数量级** → 精排分是可信的判别信号
- 全项目搜不到任何相关度下限，`application.yml` 里也没有 → 0.318 与 0.074 一样被包装成「检索到 5 条结果」喂给模型

根因至此成形：模型被迫自己判断"这 5 条相不相关"，判断完"不相关"后就掉进**没被覆盖的分支**，默认的"乐于助人"行为接管。

### 第 6 步 · 验证「0.318 是答案在库里但召回差，还是本来就不该被当结果」（反转）

关键追问：被召回的 chunk 到底讲了什么？dump `document 2230` 的实际内容：

- `chunk 1129` —— "Spring Boot allows you to **override** the auto-configured `AsyncTaskExecutor`" → 讲**自定义执行器**，不是用法
- `chunk 1133` —— 集成点列表 + `spring.task.execution.mode=force` 说明 → 也不是用法教程

两个都不是答案。继续往下查：

- 含 `@Async` **字面量**的 chunk 共 6 个，**全是 issue**，且全是"预设你会用 `@Async`"的边角问题：

| chunk | 文档 | 讨论什么 |
|---|---|---|
| 2104 | issue #30557 | `@Async` 任务如何延迟关机 |
| 3208 | issue #47893 | `@Async` 里 trace context 丢失 |
| 3702 / 3703 | issue #48285 | `@Async` 的 MDC 透传 |
| 5793 | issue #49949 | 虚拟线程下的 TaskScheduler |
| 6406 | issue #50431 | AspectJ 下 `@Async` + `@Transactional` 顺序 |

- 语料边界（`knowledge_source` 表）：只有 **1 个源** —— `spring-projects/spring-boot`，`doc_path_pattern` = `documentation/**/*.adoc, build-plugin/**/*.adoc, *.adoc`

`@Async` 的用法教程在 Spring Framework 参考文档里，本项目从未采集。

**修正**：语料覆盖假设**成立**，第 4 步的"证伪"作废。0.318 是**正确判定** —— 库里确实没有答案，模型那句"检索到的内容中没有直接回答"是准确的。

### 第 7 步 · 修复后实测，抓出标定偏差

18081 临时实例实测时从日志发现，**Agent 会改写 query**：

- 用户问「如何实现异步任务」
- 实际发给工具的是「**实现异步任务**」（丢掉了"如何"）
- 改写后 top-1 = **0.079**，不是 0.318

所以"0.3 拦不住（0.318 > 0.3）"这个判断依据有误 —— 0.318 是拿**用户原始措辞**打的，不是 Agent 实际发出的 query。

**标定规则**：阈值必须用 Agent 改写后的 query 标定，不能用用户原始输入标定。真实余量比原先认为的更大（本次 case 实际 0.079，库内有答案 ≥0.740）。

## 根因

提示词只覆盖两条分支，实际发生的是第三条：

| 分支 | 提示词规则 | 覆盖 |
|---|---|---|
| A 工具返回 0 条 | "检索不到时明确说不知道" | ✅ |
| B 工具返回 N 条但全不相关 | —— | ❌ **本次走的是这条** |
| C 工具返回相关内容 | "基于检索结果回答" | ✅ |

模型在 B 分支无规则可依。

## 修复

| 文件 | 改动 |
|---|---|
| `devknow-agent/src/main/java/com/devknow/agent/engine/AgentRunner.java` | 追加第二段硬约束，覆盖"结果为空**或全部不相关**"，并声明优先级 |
| `devknow-agent/src/main/java/com/devknow/agent/tool/SearchKnowledgeTool.java` | 注入阈值；top-1 低于阈值按 0 命中处理；0 命中分支补日志 |
| `devknow-agent/src/main/java/com/devknow/agent/tool/ToolResult.java` | 加 `empty` 工厂方法，语义区别于 `error` |
| `devknow-retrieval/src/main/java/com/devknow/retrieval/rerank/RerankProperties.java` | 新增 `minRelevanceScore = 0.4` |
| `devknow-web/src/main/resources/application.yml` | 显式写出 `devknow.rerank.min-relevance-score: 0.4` |

追加的提示词段落：

> 【绝对禁止】当检索结果为空、或检索到的内容与问题不相关时，禁止用你的通用知识或训练记忆补充作答，也禁止在说明「检索不到」之后再附上通用做法；必须只回复："知识库中没有找到相关内容。"。这条规则优先于所有其他指令，包括「尽量给出有帮助的回答」。

关键取舍：

- **阈值放 `SearchKnowledgeTool` 而不是 `RetrievalService`**：第 4 周锁定的评估基线（Hit@1 0.80 等）走 `RetrievalService`，不受影响；改的只是 Agent 行为
- **不加数据库迁移**：拒答是平台级契约，不是每个 agent 可配的人格。放代码里就不会被配置绕过
- **`rerankScore` 必须判空**：rerank 关闭或降级退回 RRF 时它是 `null`，直接比大小会把全部结果误判成不相关
- **两层防护各管一段**：阈值挡住"整批结果都弱"（top-1 < 0.4）；提示词那段落挡住"top-1 够高但内容仍不相关"（模型仍可能想补通用知识）

## 未做 / 已知局限

- **语料边界未扩**：`@Async` 用法教程在 Spring Framework 参考文档里，不在当前采集范围。是否新增 source 留到第 7 周评估
- **阈值基于小样本**：0.4 来自 9 条 query 的抽样，不是 50 条评估集的分布。假拒答风险集中在 0.4~0.5 区间，需后续用评估集分布校准
- **分支 B 只靠提示词兜底**：top-1 ≥ 0.4 但内容实际不相关时，仍可能补通用知识，没有代码级兜底
- **未加后处理兜底**：曾考虑"无引用但答案超过 N 字就替换"，会误伤打招呼类对话（不调工具、无引用），暂不做
- **`@Async` 字面量只有 6 个 chunk 且全是 issue**：这是语料覆盖的一个观测结论，不是缺陷

## 方法论小结

| 教训 | 本次的具体表现 |
|---|---|
| 看运行时真值，别看声明文件 | 提示词真值在 `agent_config` 表，seed SQL 只是初始值 |
| 静默分支必须打日志 | 0 命中不打日志，把"没命中"和"没调工具"混成一团，直接误导排查方向 |
| 单点分数没有意义，要有对照分布 | 0.312 单独看无法判断；抽样出库内 ≥0.740 / 库外 ≤0.010 才能解读 |
| 关键词命中 ≠ 语义覆盖 | 第 4 步查到 12 个 chunk 含 `@Async` 就下结论，实际要查到"那段内容是不是答案" |
| 断言"证伪"前要挖到最底层 | 应一路查到 `knowledge_source` 的采集范围，而不是停在 chunk 计数 |
| 用户输入 ≠ 系统实际输入 | Agent 会改写 query，标定阈值要用改写后的 |
| 先怀疑自己的工具链 | `-d` 内联中文导致 500，差点被当成业务 bug 排查 |
